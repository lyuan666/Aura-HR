## Context

在原有三大功能（飞书集成、邮箱归集、Chrome 插件）基础上，根据业务扩张需求，新增了 **甲方客户协同门户 (Client Portal)** 以及 **全局移动端适配 (Mobile Responsiveness)** 两大核心需求。

**本次计划完善点**：
引入了现代工程化构建工具、OAuth2 现代邮箱鉴权标准、反风控高级策略，以及面向客户侧的轻量化工作流（可内嵌钉钉/飞书）和全端的响应式 UI 设计规范。

---

## 功能 A: 飞书集成（消息推送 + 日历同步）

### A0. 现状
- 已有内部飞书表格导入逻辑，但缺乏外部系统通知基础设施。
- 需要实现内部猎头提醒与外部客户消息推送。

### A1. 后端 - NotificationModule
- 统一通知服务，处理飞书 Token 缓存、刷新及限流（Exponential Backoff）。
- 提供交互式卡片消息（Interactive Card），支持颜色标识状态、携带直达链接。
- **与新需求结合**：为后续的**甲方门户**提供基础，当发送"推荐报告"时，直接推送飞书卡片给甲方 HR，HR 点击卡片能在飞书内免登直接打开 H5 门户。

### A2. 接入业务通知钩子
- 推荐状态变更、面试安排、收到甲方新岗位需求时，均触发通知。
- 失败降级：通知失败不阻塞主业务。

## 功能 B: 邮箱归集

### B1. 后端 - EmailModule
- **鉴权**：支持 OAuth2.0 以接入现代化邮箱（Gmail/Outlook），兼容 IMAP。
- **解析防 OOM**：使用 Node.js Stream 读取并解析邮件，避免大附件打爆内存。
- **智能关联**：基于发件人/正文邮箱，将邮件、附件（简历）自动挂载至候选人 Timeline。

### B2. 前端展示
- 新增独立邮箱配置收件箱页面。
- 候选人详情中增加 "邮件往来" 独立 Tab。

---

## 功能 C: Chrome 插件（候选人信息采集）

### C1. 技术选型 (Plasmo)
- 采用 **Plasmo (React + Tailwind + V3)** 框架，构建现代扩展程序，隔离样式，不污染原页面。

### C2. 降维打击级反风控
- 放弃硬编码 DOM 提取，使用 `world: 'MAIN'` 脚本直接劫持宿主网站 Window 对象中的现代前端状态（如 Vue/React Store），获取 100% 准确的 JSON 简历源数据。
- 配合拟人化行为（随机延迟、平滑滚动加载全页）。

## 功能 D: 甲方客户协同门户 (Client Portal) ✨ (新增)

### D0. 核心定位
- **独立入口**：与内部核心系统隔离，拥有独立的前端路由空间（如 `app/(portal)`）或子域名。
- **生态内嵌**：专为移动办公设计，**必须能够无缝内嵌至飞书、钉钉等工作台**，方便甲方 HR 随时随地处理业务。

### D1. 核心功能设计
1. **推荐报告查阅与流转**：
   - 甲方 HR 可查看猎头推荐的候选人报告（支持关键信息脱敏）。
   - 可直接在页面上操作候选人状态（如：通过初筛、淘汰、预约面试），数据实时同步至猎头内部系统并通知对应猎头。
2. **岗位需求 (Job Requirement) 提交与管理**：
   - 允许甲方 HR 创建和优化最新的岗位需求。
   - **代码复用**：在后端直接复用 `JobService` 逻辑；前端提取现有的岗位表单组件进行裁剪。
   - 甲方提交后，自动在内部系统关联该企业，状态置为"待分配/寻访中"。

### D2. 免登与鉴权体系 (OAuth/Magic Link)
- 飞书/钉钉内嵌时，对接平台的免登 API（SSO）。
- 也可以通过邮件/飞书发送带有 JWT 的 Magic Link（短链接），HR 点击后直接以该项目/岗位的权限进入页面，无需记住繁琐的账密。

## 功能 E: 全局移动端适配优化 (Mobile Responsiveness) ✨ (新增)

### E0. 核心痛点
当前 Ant Design/Tailwind 构建的后台偏向 PC 端，手机浏览器中 Drawer（抽屉）、复杂 Table 和宽表单体验极差。内部系统与新增的甲方门户均需彻底优化。

### E1. 优化策略
1. **弹性布局重构**：
   - 引入 Tailwind 的响应式断点（`sm:`, `md:`, `lg:`）。
   - PC 端的双栏（如左列表，右详情 Drawer）在移动端自动转换为单栏（列表点击后路由跳转或全屏 Modal 覆盖）。
2. **数据展示降级 (Table -> Card)**：
   - 在手机端隐藏复杂的 Antd Table。
   - 替换为信息流卡片（Card List），只展示核心字段（姓名、匹配度、最新状态），点击卡片查看详情。
3. **交互组件替换**：
   - 将侧边导航栏改造为移动端底栏（Bottom Navigation）或顶部汉堡菜单（Hamburger Menu）。
   - 放大输入框、按钮的触控热区（至少 `44px` 高度）。
   - 优化下拉选择器（Select）为移动端原生的底部 ActionSheet 或 Picker。
