## 3. 核心模块设计

### 3.1 文件暂存 — 解决"批量不崩"

**现状**: `FileInterceptor` 把整个文件放内存，批量时 OOM。

**方案**: 文件先存 MinIO（已部署），BullMQ 只传文件引用。

```typescript
// 上传接口 — 只做文件接收，不做解析
@Post('upload')
@UseInterceptors(FileInterceptor('file'))
async uploadResume(@UploadedFile() file: Express.Multer.File, @Req() req) {
  // 1. 存原始文件到 MinIO
  const fileKey = `resumes/${req.user.tenantId}/${uuid()}-${file.originalname}`;
  await this.minioService.putObject('uploads', fileKey, file.buffer, file.size);

  // 2. 算文件指纹 (后续去重用)
  const fileHash = createHash('sha256').update(file.buffer).digest('hex');

  // 3. 投递解析任务到 BullMQ (确定性 jobId 防重复入队)
  const job = await this.parseQueue.add('parse-resume', {
    tenantId: req.user.tenantId,
    fileKey,
    fileName: file.originalname,
    fileSize: file.size,
    fileHash,
    sourcePlatform: 'manual_upload',
  }, {
    jobId: `parse-${fileHash}`,   // 确定性 ID: 同一文件不重复入队
    attempts: 3,
    backoff: { type: 'exponential', delay: 5000 },
  });

  return { jobId: job.id, status: 'queued' };
}

// 批量上传
@Post('batch-upload')
@UseInterceptors(FilesInterceptor('files', 100))
async batchUpload(
  @UploadedFiles() files: Express.Multer.File[],
  @Req() req,
  @Body('sourcePlatform') sourcePlatform?: string,
) {
  const batchId = uuid();
  const results = [];

  for (const file of files) {
    const fileKey = `resumes/${req.user.tenantId}/${batchId}/${uuid()}-${file.originalname}`;
    const fileHash = createHash('sha256').update(file.buffer).digest('hex');

    await this.minioService.putObject('uploads', fileKey, file.buffer, file.size);

    const job = await this.parseQueue.add('parse-resume', {
      batchId,
      tenantId: req.user.tenantId,
      fileKey,
      fileName: file.originalname,
      fileSize: file.size,
      fileHash,
      sourcePlatform: sourcePlatform || 'manual_upload',
    }, {
      jobId: `parse-${fileHash}`,
      attempts: 3,
      backoff: { type: 'exponential', delay: 5000 },
    });

    results.push({ fileName: file.originalname, jobId: job.id });
  }

  return { batchId, total: files.length, jobs: results };
}
```

### 3.2 PDF → 结构化 Markdown (替换 pdf-parse)

**问题**: `pdf-parse` 输出毫无层级的粘连纯文本，LLM 无法区分"工作经历"和"项目经历"的分界线，导致张冠李戴。

**方案**: 集成 **MinerU** — 专为中文 PDF 优化的结构化提取工具。

| 工具 | Stars | 中文 | 结构保留 | 许可证 | 集成方式 |
|------|-------|------|---------|--------|---------|
| **MinerU** | 25k+ | 最佳 | 表格/标题/列表/公式 | Apache 2.0 | REST API 微服务 |
| Docling (IBM) | 10k+ | 好 | 表格/标题/图片 | MIT | REST API |
| Marker | 20k+ | 好 | 表格/标题/列表 | GPL-3.0 | CLI |
| pdf-parse | - | 差 | 无 (粘连纯文本) | MIT | npm |

**MinerU 微服务部署**:

```yaml

    - MINERU_PARSE_METHOD=auto    # auto / ocr / txt

**性能基准**:

| 配置 | 3 页 PDF 耗时 | 适用场景 |
|------|-------------|---------|
| GPU (NVIDIA T4) | ~2-3s | 生产环境推荐 |

**CPU Fast Mode 调用**: 无 GPU 时，禁用版面分析和公式识别换取速度：

```typescript
private async extractWithMinerU(buffer: Buffer): Promise<string> {
  const isGpuAvailable = process.env.MINERU_DEVICE === 'cuda';

  const formData = new FormData();
  formData.append('file', new Blob([buffer]), 'resume.pdf');

  // CPU 模式: 禁用 layout 和 formula 检测，仅做文本+表格提取
  const params = isGpuAvailable ? {} : {
    parse_method: 'ocr',       // 跳过 YOLO 版面分析
    disable_formula: 'true',   // 不做公式识别
    disable_table: 'false',    // 保留表格提取 (简历核心需求)
  };

  const response = await axios.post(
    `${process.env.MINERU_URL || 'http://mineru:8000'}/pdf/parse`,
    formData,
    { timeout: 30000, params, headers: { 'Content-Type': 'multipart/form-data' } }
  );

  return response.data.markdown || response.data.content;
}

**文本提取管线 — 三级降级**:

```typescript
// apps/api/src/modules/ai/pdf-extraction.service.ts

export class PdfExtractionService {

  /**
   * 提取结构化文本
   * 返回 Markdown 格式 (保留标题/列表/表格层级)
   */
  async extractStructuredText(fileKey: string, fileName: string): Promise<ExtractedContent> {
    const buffer = await this.minioService.getObject('uploads', fileKey);
    const ext = path.extname(fileName).toLowerCase();

    // DOCX → mammoth (已有，效果尚可)
    if (ext === '.docx') {
      const text = await extractTextFromDocx(buffer);
      return { text, format: 'plain', method: 'mammoth' };
    }

    // TXT → 直接返回
    if (ext === '.txt') {
      return { text: buffer.toString('utf-8'), format: 'plain', method: 'direct' };
    }

    // PDF → 结构化提取管线
    if (ext === '.pdf') {
      // Level 1: MinerU → Markdown (保留标题/列表/表格)
      try {
        const md = await this.extractWithMinerU(buffer);
        if (md.length > 30) {
          return { text: md, format: 'markdown', method: 'mineru' };
        }
      } catch (e) {
        this.logger.warn(`MinerU 提取失败，降级到 pdf-parse: ${e.message}`);
      }

      // Level 2: pdf-parse 降级 (粘连文本，但总比没有强)
      try {
        const text = await extractTextFromPdf(buffer);
        if (text.length > 50) {
          return { text, format: 'plain', method: 'pdf-parse' };
        }
      } catch (e) {
        this.logger.warn(`pdf-parse 也失败，降级到视觉模型`);
      }
    }

    // Level 3: 视觉模型 OCR (扫描件/图片)
    if (['.pdf', '.jpg', '.jpeg', '.png'].includes(ext)) {
      const visionText = await this.llmRouter.extractWithVision(buffer);
      if (visionText.length > 20) {
        return { text: visionText, format: 'plain', method: 'vision' };
      }
    }

    throw new Error(`无法提取文件内容: ${fileName}`);
  }

  /**
   * MinerU 微服务调用
   */
  private async extractWithMinerU(buffer: Buffer): Promise<string> {
    const formData = new FormData();
    formData.append('file', new Blob([buffer]), 'resume.pdf');

    const response = await axios.post(
      `${process.env.MINERU_URL || 'http://mineru:8000'}/pdf/parse`,
      formData,
      { timeout: 30000, headers: { 'Content-Type': 'multipart/form-data' } }
    );

    // MinerU 返回 Markdown 格式，保留标题/列表/表格结构
    return response.data.markdown || response.data.content;
  }
}

interface ExtractedContent {
  text: string;       // Markdown 或纯文本
  format: 'markdown' | 'plain';
  method: 'mineru' | 'pdf-parse' | 'mammoth' | 'vision' | 'direct';
}
```

### 3.3 LLM 路由器 — 全局分布式限流

**问题**: 原方案用内存 `Semaphore(3)` 限流，多 Pod 部署时每个实例独立计数，总并发 = 3 × Pod 数，打爆 API 429。

**方案**: 用 `redis-semaphore` 实现基于 Redis 的分布式信号量。

```typescript
// apps/api/src/modules/ai/llm-router.service.ts

import { Semaphore } from 'redis-semaphore';
import Redis from 'ioredis';

export class LlmRouterService implements OnModuleDestroy {
  private redis: Redis;
  private semaphore: Semaphore;

  constructor() {
    this.redis = new Redis(process.env.REDIS_URL || 'redis://localhost:6379');

    // 分布式信号量: 跨所有 Pod 共享，全局最多 N 个并发 LLM 调用
    this.semaphore = new Semaphore(
      this.redis,
      'llm:api:concurrency',                    // Redis key
      parseInt(process.env.LLM_CONCURRENCY || '3'),  // 最大并发数
      {
        lockTimeout: 120000,   // 单次调用最长 120s (防死锁)
        acquireTimeout: 60000, // 最多等 60s 获取信号量
        retryInterval: 200,    // 每 200ms 重试
      }
    );
  }

  /**
   * 调用 LLM — 全局并发安全
   * 无论部署多少个 Pod，总并发不超过 LLM_CONCURRENCY
   */
  async callProvider(provider: 'resume' | 'vision' | 'embedding', messages: any[]): Promise<any> {
    await this.semaphore.acquire();
    try {
      const config = this.getProviderConfig(provider);
      try {
        return await this.doCall(config.primary, messages);
      } catch (e) {
        if (config.fallback?.url) {
          return await this.doCall(config.fallback, messages);
        }
        throw e;
      }
    } finally {
      await this.semaphore.release();
    }
  }

  /**
   * 调用 LLM — 全局并发安全 + JSON 输出鲁棒性
   */
  async callForJson(provider: 'resume' | 'vision' | 'embedding', messages: any[]): Promise<any> {
    const raw = await this.callProvider(provider, messages);
    return this.extractJson(raw);
  }

  /**
   * 鲁棒 JSON 提取 — 处理 LLM 输出的各种"自作聪明"
   *
   * LLM 常见的非标输出:
   * 1. ```json\n{...}\n```           — Markdown 代码块包裹
   * 2. 好的，以下是解析结果：\n{...}  — 前面有寒暄语
   * 3. {...}\n以上是结果。            — 后面有总结语
   * 4. {..."reason": "他说："好的""} — JSON 内部包含未转义引号
   */
  private extractJson(raw: string): any {
    // Step 1: 去掉 markdown 代码块包裹
    let cleaned = raw
      .replace(/^```(?:json)?\s*\n?/i, '')
      .replace(/\n?```\s*$/i, '')
      .trim();

    // Step 2: 找到第一个 { 和最后一个 } 之间的内容
    const start = cleaned.indexOf('{');
    const end = cleaned.lastIndexOf('}');
    if (start === -1 || end === -1 || end <= start) {
      throw new Error(`LLM 输出不含有效 JSON: ${raw.substring(0, 200)}`);
    }
    cleaned = cleaned.substring(start, end + 1);

    // Step 3: 尝试直接解析
    try {
      return JSON.parse(cleaned);
    } catch (_) {
      // Step 4: 修复常见的 JSON 格式问题
      // - 未转义的换行符
      // - 尾部逗号 (JSON 标准不允许)
      // - 单引号代替双引号
      const repaired = cleaned
        .replace(/,\s*([}\]])/g, '$1')           // 去尾部逗号
        .replace(/'/g, '"');                      // 单引号 → 双引号

      try {
        return JSON.parse(repaired);
      } catch (_) {
        // Step 5: 最终兜底 — 逐层剥离尝试
        throw new Error(`JSON 解析失败，原始输出: ${raw.substring(0, 300)}`);
      }
    }
  }

  // 模型配置 — 全部走环境变量
  private getProviderConfig(provider: string) {
    const envPrefix = `LLM_${provider.toUpperCase()}_`;
    return {
      primary: {
        url: process.env[`${envPrefix}URL`],
        model: process.env[`${envPrefix}MODEL`],
        key: process.env[`${envPrefix}KEY`],
      },
      fallback: {
        url: process.env[`${envPrefix}FALLBACK_URL`],
        model: process.env[`${envPrefix}FALLBACK_MODEL`],
        key: process.env[`${envPrefix}FALLBACK_KEY`],
      },
    };
  }

  onModuleDestroy() {
    this.redis.disconnect();
  }
}
```

**为什么不用 BullMQ 内置 limiter?** BullMQ 的 `limiter` 是速率限制（每秒 N 次），不是并发限制（同时 N 个在飞）。LLM API 厂商通常限制的是同时并发连接数，不是 QPS。`redis-semaphore` 精确控制全局并发，语义匹配。

**部署对比**:

| | 内存 Semaphore | redis-semaphore |
|---|---|---|
| 单实例 | 正常 | 正常 |
| 3 个 Pod | 总并发 = 9 (越界) | 总并发 = 3 (精确) |
| 协调机制 | 无 | Redis Sorted Set + Lua |
| 性能开销 | 0 | ~1ms acquire/release |
| 死锁风险 | 无 | 有 (120s 超时自动释放) |

### 3.4 去重 — 四层防护

```
上传文件
    │
    ├── Layer 1: 文件指纹 (SHA256) ── 完全相同文件秒拒
    │   → 索引: file_hash
    │   → 命中率: 10% (重复上传同一份文件)
    │
    ├── Layer 1.5: 文本内容指纹 (Text Hash) ── 同内容不同文件
    │   → 归一化文本 (去空白/换行/大小写) → SHA256
    │   → 索引: text_hash
    │   → 命中率: 15-20% (HR 改了格式但内容一样)
    │
    ├── Layer 2: 精确匹配 (手机/邮箱) ── 同一人不同来源
    │   → 索引: phone, email
    │   → 命中率: 60-70%
    │
    └── Layer 3: 中文模糊匹配 (姓名+公司) ── 无手机邮箱时
        → cn_name_similarity() 函数
        → 命中率: 10-15%
```

**新增 Layer 1.5: 文本内容指纹**

```typescript
// 解决: HR 打开 PDF 加个空格重新导出 → SHA256 变了，但内容没变
// 方案: 白名单策略 — 只保留中文、英文字母、数字，丢弃所有其他字符
// 原因: MinerU 的 Markdown 输出包含 |---#* 等排版符号，
//       不同版本或换解析器时这些符号会变，导致同一简历算出不同 Hash

function computeTextHash(text: string): string {
  const normalized = text
    .replace(/[^\u4e00-\u9fa5a-zA-Z0-9]/g, '')  // 只保留: 中文 + 字母 + 数字
    .toLowerCase();
  return createHash('sha256').update(normalized).digest('hex');
}
```

**Layer 3: 中文模糊匹配函数**

pg_trgm 不适合中文（基于 3 字节 trigram，对 UTF-8 中文无意义）。用自定义函数：

```sql
-- 中文公司名相似度函数
-- 去掉地名前缀和公司后缀后比较
CREATE OR REPLACE FUNCTION cn_name_similarity(a text, b text)
RETURNS float AS $$
DECLARE
  ca text;
  cb text;
BEGIN
  -- 去掉常见公司名称后缀
  ca := regexp_replace(a, '(有限责任|有限|股份|集团|公司|科技|网络技术|信息技术|技术服务中心)$', '');
  cb := regexp_replace(b, '(有限责任|有限|股份|集团|公司|科技|网络技术|信息技术|技术服务中心)$', '');
  -- 去掉地区前缀
  ca := regexp_replace(ca, '^(北京|上海|广州|深圳|杭州|浙江|江苏|四川|广东|中国)', '');
  cb := regexp_replace(cb, '^(北京|上海|广州|深圳|杭州|浙江|江苏|四川|广东|中国)', '');

  -- 一个包含另一个 → 高相似度
  IF ca = '' OR cb = '' THEN RETURN 0; END IF;
  IF position(cb in ca) > 0 OR position(ca in cb) > 0 THEN
    RETURN 0.85;
  END IF;

  -- 否则用编辑距离归一化
  RETURN 1.0 - (levenshtein(ca, cb)::float / GREATEST(length(ca), length(cb)));
END;
$$ LANGUAGE plpgsql IMMUTABLE;
```

```typescript
// 去重逻辑 — 四层完整实现

async checkDuplicate(
  profile: CandidateProfile,
  tenantId: string,
  textHash: string,
): Promise<DupCheckResult> {
  const params: any = { tenantId };

  // Layer 1.5: 文本内容指纹 (新增)
  const textDup = await this.repo
    .createQueryBuilder('c')
    .where('c.tenantId = :tenantId AND c.text_hash = :textHash', { tenantId, textHash })
    .getOne();
  if (textDup) {
    return { isDuplicate: true, candidateId: textDup.id, matchField: 'text_hash', confidence: 0.99 };
  }

  // Layer 2: 精确匹配 — 手机或邮箱
  const conditions: string[] = [];
  if (profile.phone) { conditions.push('c.phone = :phone'); params.phone = profile.phone; }
  if (profile.email) { conditions.push('c.email = :email'); params.email = profile.email; }

  if (conditions.length > 0) {
    const exact = await this.repo
      .createQueryBuilder('c')
      .where(`c.tenantId = :tenantId AND (${conditions.join(' OR ')})`)
      .setParameters(params)
      .getOne();
    if (exact) {
      return { isDuplicate: true, candidateId: exact.id, matchField: 'phone_or_email', confidence: 0.95 };
    }
  }

  // Layer 3: 中文模糊匹配 — 姓名 + 公司名相似度
  if (profile.name && profile.currentCompany) {
    const fuzzy = await this.repo
      .createQueryBuilder('c')
      .where('c.tenantId = :tenantId AND c.name = :name', { tenantId, name: profile.name })
      .andWhere(`cn_name_similarity(c.currentCompany, :company) > 0.7`, { company: profile.currentCompany })
      .getOne();
    if (fuzzy) {
      return { isDuplicate: true, candidateId: fuzzy.id, matchField: 'name+company_fuzzy', confidence: 0.7 };
    }
  }

  return { isDuplicate: false };
}

### 3.5 幂等入库 — 解决崩溃重试产生脏数据

**问题**: Worker 执行 `INSERT` 成功后、投递向量化队列前崩溃。BullMQ 重试时重复入库。

**方案**: 唯一约束 + `ON CONFLICT` + 确定性 jobId。

```typescript
// BullMQ Worker — 幂等设计

@Process('parse-resume')
async handleParse(job: Job<ParseJob>) {
  const result = await this.parsingV2.parseResume(job.data);

  if (result.status === 'duplicate') {
    return { status: 'duplicate', existingId: result.existingCandidateId };
  }

  // 幂等入库: ON CONFLICT DO NOTHING
  // 唯一键: (file_hash, tenantId) — 同一文件同一租户只能入库一次
  const candidate = await this.candidateService.createIfNotExists({
    ...result.profile,
    tenantId: job.data.tenantId,
    sourcePlatform: job.data.sourcePlatform,
    fileHash: job.data.fileHash,
    textHash: result.textHash,
  });

  if (!candidate) {
    // 已存在 (被其他 Worker 或重试创建)
    return { status: 'duplicate', matchField: 'file_hash' };
  }

  // 确定性 jobId 防止向量化任务重复入队
  await this.vectorizeQueue.add('vectorize', {
    candidateId: candidate.id,
  }, {
    jobId: `vec-${candidate.id}`,   // 同一候选人只产生一个向量化任务
    attempts: 5,
    backoff: { type: 'exponential', delay: 3000 },
  });

  return { status: 'success', candidateId: candidate.id };
}
```

```typescript
// CandidateService — 幂等创建，始终返回候选人 ID

async upsertByFileHash(dto: CreateCandidateDto): Promise<{ id: string; isNew: boolean }> {
  // ON CONFLICT DO UPDATE (不实际改数据，只为触发 RETURNING 拿到已有 ID)
  const result = await this.repo.createQueryBuilder()
    .insert()
    .values(dto)
    .onConflict(`("file_hash", "tenantId") DO UPDATE SET "updatedAt" = "updatedAt"`)
    .returning(['id'])
    .execute();

  // 区分新建 vs 已有: 比较返回的 updatedAt 和 createdAt
  // 更简单的做法: 先查是否存在
  const isNew = !await this.repo.findOne({
    where: { fileHash: dto.fileHash, tenantId: dto.tenantId },
    select: ['id'],
  });

  return { id: result.raw[0].id, isNew };
}
```

> `isNew` 标记让 Worker 知道是否需要投递向量化任务（已有记录可能已向量化过）。

### 3.6 实时进度推送 — SSE (替换轮询)

**问题**: 每 2s 轮询批量状态，批量处理时产生大量无效 DB 查询。

**方案**: Server-Sent Events，NestJS 原生 `@Sse()` 支持。

```typescript
// apps/api/src/modules/candidate/progress.service.ts

import { Injectable } from '@nestjs/common';
import { Subject, map } from 'rxjs';

export interface JobProgress {
  jobId: string;
  batchId?: string;
  fileName: string;
  progress: number;    // 0-100
  status: 'queued' | 'extracting' | 'parsing' | 'deduping' | 'saving' | 'completed' | 'duplicate' | 'failed';
  result?: any;
  error?: string;
}

@Injectable()
export class ProgressService {
  private subjects = new Map<string, Subject<JobProgress>>();

  emit(event: JobProgress) {
    const key = event.batchId || event.jobId;
    if (!this.subjects.has(key)) {
      this.subjects.set(key, new Subject<JobProgress>());
    }
    this.subjects.get(key)!.next(event);

    // 完成后延迟清理 Subject
    if (['completed', 'duplicate', 'failed'].includes(event.status)) {
      setTimeout(() => this.subjects.delete(key), 60000);
    }
  }

  getStream(key: string) {
    if (!this.subjects.has(key)) {
      this.subjects.set(key, new Subject<JobProgress>());
    }
    return this.subjects.get(key)!.pipe(
      map(event => ({ data: JSON.stringify(event) }) as MessageEvent)
    );
  }
}
```

```typescript
// apps/web/src/lib/useBatchProgress.ts

function useBatchProgress(batchId: string) {
  const [files, setFiles] = useState<Map<string, JobProgress>>(new Map());

  useEffect(() => {
    const es = new EventSource(`/api/candidates/upload-progress/${batchId}`);

    es.onmessage = (e) => {
      const event: JobProgress = JSON.parse(e.data);
      setFiles(prev => new Map(prev).set(event.jobId, event));

      // 批次内所有文件完成时关闭连接
      // (由前端根据 total 和 completed 计数判断)
    };

    es.onerror = () => es.close();
    return () => es.close();
  }, [batchId]);

  return files;
}
```

**SSE vs 轮询对比**:

| | 轮询 (2s) | SSE |
|---|---|---|
| 延迟 | 0-2s | <100ms (实时) |
| 50 文件批量时 DB 查询 | ~250 次 (每文件 5 轮询) | 0 次 |
| 网络请求数 | ~250 | 1 (长连接) |
| 复杂度 | 低 | 中 |
| 多实例支持 | 天然支持 | 需 Redis Pub/Sub |

**多实例部署说明**: SSE 的 Subject 存在内存中。如果部署多个 NestJS Pod，需要通过 Redis Pub/Sub 在 Worker 进程和 SSE 连接所在进程之间转发事件。单实例部署时无需额外处理。

### V2.1 → V2.2

| 问题 | 原方案 | V2.2 修正 |

| text_hash 黑名单归一化遗漏 Markdown 排版符号 | 枚举标点 `replace(/[，。...]/g, '')` | **白名单策略** `[^\u4e00-\u9fa5a-zA-Z0-9]` 只保留中文+字母+数字 |
